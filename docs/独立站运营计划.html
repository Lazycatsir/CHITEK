零、目标客户画像（一切的前提）

这一节回答：我们想要谁来点这个网站、他点进来时脑子里在想什么。关键词矩阵、产品页模块顺序、周报看哪个数，全都由它决定。

第一性：一个访客不是一个人，是一条决策链上的一个角色。
ToB 工业品的访客点进来不是为了买，是为了完成自己那一步的工作——选型、比价、写规格书、找货源。所以网站的目标不是"说服他下单"，而是：帮他把那一步做完，并且留下联系方式。
发现问题（电气工程师） → 技术评估（工程师 / 设计院选型）
      → 商务（采购比价、谈条款） → 拍板（业主 / 项目经理） → 运维验收

这五个角色要的东西完全不同。网站必须同时给每个人一份"他能带走的东西"——少一份，中间就会卡住。

每类人的真实心理

① 终端电气工程师（P0）—— 最该讨好的人

他在想他要点走的证据会点的按钮
这玩意真能降到 5% 以内？还是又一个滤波器？原理讲透 + 同类工况实测前后数据下载选型手册
我的柜子放得下吗？要停电施工吗？尺寸图、安装方式（壁挂 / 机架）看参数表
出了事谁负责？会不会影响生产？质保、认证、故障处理问技术工程师
我怎么跟领导解释这笔钱？可复制进汇报材料的数字（电费 / 罚款 / 寿命）发我的工况，帮我选型
坑：他最烦"行业领先 / 品质卓越"这种话。给他公式和数据，别给他形容词。

② 海外代理商（P0）—— 出单最快，也最容易白忙

他在想他要点走的证据会点的按钮
中国同行这么多，我为什么要多推一个牌子？明确差异化（SiC、效率、尺寸、价格带）看产品线
给我的价格和保护是什么？独家区域 / 价格体系 / 样机政策Apply for distribution
你支不支持我？英文资料包、选型支持、售后培训、当地认证下载渠道政策
交期和起订量？MOQ、交期、库存直接问
坑：现在 /services 页的经销部分太薄，没有一份能下载的渠道政策文件，代理商看完无法判断"值不值得投入"。这是三类客户里性价比最高的一处补强。

③ EPC / 系统集成商（P1）—— 单点金额最大

他在想他要点走的证据
能不能过业主 / 设计院的审核？符合 IEEE 519 / IEC 61000 / G5-4 等标准清单
参数能不能直接填进招标表？完整 datasheet（含型号表）
交期会不会拖我项目？产能、交期承诺
出质量问题你担不担？质保条款、业绩清单

他要的是一整包合规文件，不是一个漂亮页面。资源中心没建起来之前，这类单基本接不住。

④ 设计院 / 咨询工程师（P1）—— 不买，但他写品牌

  • 他想：选型方法我自己要能算（容量、电压等级、接线方式）；参数要能直接抄进图纸。
  • 他要：选型指南 / 计算公式 + 完整参数 + CAD/BIM 图。
  • 这类人最吃"中性技术内容"，最烦销售腔 —— 技术文章要写成教程（教他怎么算），不能写成软文。
  • 他是唯一一类会主动把你的品牌写进别人招标文件的人，长期价值被严重低估。

⑤ OEM 贴牌（P2）

  • 他想：能不能贴我的牌、改外观改界面？最小起订量多少？你会不会哪天自己去做终端抢我客户？通信协议对得上吗？
  • 他要：OEM 能力说明 + 定制案例（脱敏）+ 产能 + 明确的"不做终端"承诺。

⑥ 采购比价（P2）—— 设计成低成本接待，别为他做内容

  • 他只想拿单价、MOQ、付款方式、交期。
  • 应对：表单加两个字段（项目名称 / 预计年用量）自动分流，别让销售在比价单上耗时间。

判别信号：怎么知道来的是哪一类人

现在表单只有 name / email / phone / message，看不出对方是谁，销售第一句话不知道怎么开口。建议加一个下拉（30 分钟能做完）：

I am a:  [ ] End-user engineer / plant owner
         [ ] Distributor / Agent
         [ ] EPC contractor / System integrator
         [ ] Design institute / Consultant
         [ ] OEM / Private label
         [ ] Procurement / Sourcing

这一个字段带来三件事：① 周报的"有效询盘"可以按角色分层；② 销售第一句就知道该给技术资料还是渠道政策；③ GA4 里可当自定义维度，看哪类人转化率最高。

先服务谁：P0 = 终端电气工程师 + 海外代理商。
① 素材现成 —— 18 个行业案例 + 26 篇英文文章正好是喂给工程师的东西；
② 代理商最快出单量，只需要一份渠道政策 PDF 就能启动，不依赖技术部给参数；
③ EPC 和设计院强依赖"资料包"（datasheet / CAD / 证书），排在技术部给出文件之后 —— 资料不到，这一块做不了。

同义词变体：不建换皮页，用 FAQ 承接（2026-09 实测）

背景：AHF / APF / ADF 指的是同一种设备，只是叫法不同。竞品（YT 电气）的做法是——给每个叫法单建一个页面，用多个变体页去接所有可能的搜索词。

现象证据
变体词确实有流量搜 APF 相关商业词，它的 APF 独立页排到第 4
但堆卡的分类页无效那张堆了 8 张同义词卡的分类页没排上
变体页是换皮多个变体页描述逐字复制同一段，PQF 页里仍写着 "AHF is…" → 符合 Google doorway page（换皮页）特征

规则（照做）：

  1. 同一产品不建多个同义词变体页。Google 能理解同义词，一个权威页本身就可能在 AHF / APF / active power filter 上同时拿到展现。
  2. 同义词放这三个位置：详情页正文首段（"also known as APF / ADF"）+ FAQ（"AHF、APF、ADF 有什么区别？"）+ FAQPage Schema。零成本，还顺带解决顾客"这几个到底啥区别"的困惑。
  3. 唯一例外：某变体在你的目标市场确实是主流叫法（如部分亚洲/欧洲市场习惯说 APF），才建一个独立页——内容必须与该市场绑定（当地标准、当地案例、当地语言习惯），不许复制主页面。
  4. ADF 不碰：这个词被 Comsys 官网 + 全球代理占满（ADF 是它的产品线名，不是通用词），投入产出比最差。
  5. 自检方法（零成本）：GSC → 效果 → 查询词，看同一条 URL 是否同时收到 AHF 和 APF 的展现。如果是，说明 Google 已经在做同义匹配，不必再建页。
为什么新站尤其不能学这套：域名权重低的时候，5 个薄页面每个权重都不够，谁也排不进前三；不如把权重集中到一个厚页面上。数量战术是高权重站才玩得起的。

关于"子网站 / 副本站做外链"（PBN 站群）

现象：有些公司建一批看似独立、实为自己控制的小网站，全部链向主站，人为制造大量外链。短期确实有效，所以有人做。

为什么不能做：这是谷歌官方明文定义的外链作弊。SpamBrain 识别站群的指纹包括——同一 IP 段或服务器、相同 whois 注册信息、相同模板 / GA 统计代码、内容雷同且质量低、站内几乎所有链接都指向同一个主站。一旦识别：链接权益全部作废，且主站一并降权（连坐）。惩罚常延迟 6–18 个月，所以你会看到有些站"现在还好好的"。

B2B 工业品尤其不该做：客户是项目型大企业，会查供应商线上口碑，主站被降权等于自拆询盘渠道；做长期品牌，站群是短期收益 + 长期负资产；一次被罚恢复以年计。

六、底层原理：权重与排名机制

这一节回答「上面那些规则为什么成立」。不是理论课，是判断依据——遇到新情况（要不要多建一页？要不要合并两页？）回来对一下就清楚。

6.1 权重是「流量」，不是「存量」

最常见的误解：把一个页面放着不动，权重会自己涨。不会。

权重本质是投票——外链、品牌搜索、用户从搜索结果点进来并停留，都是"这一页值得信任"的一票。票从外面流进来，再经站内链接分配到各页面。

关键：流进来的总量，跟你有多少个页面无关。它不是乘法，是分配。

6.2 为什么是「分摊」——它不是被判断出来的

不存在"Google 判断出你在分摊然后扣分"这一步。分摊是链接计算的算术必然。

一个页面传给下一个的分量 = 自己的分量 ÷ 自己的出链总数

分母是出链数。首页有 100 分、链向 10 个页面 → 每个得 10；链向 30 个 → 每个得 3.3。这跟"两个页面是不是同义词"毫无关系，纯粹是除法。

可直接用的推论：内链要集中。一个页面若出现在全站侧栏（出链极多），它分给目标页面的分量极薄；正文里少数几个精准内链，传递效率反而高得多。

6.3 雷同为什么会被「折叠」——不是扣分

应用在哪：① §二 同义词变体——不建换皮页、改用 FAQ 承接，就是怕被折叠；② §三 8 个产品页模板一致，但每个必须写透不同产品，不能互相复制。

这部分才真的有检测，流程是：

  1. 生成指纹：正文切成重叠片段、哈希，得到页面指纹
  2. 比对相似度：两页指纹相似度超阈值 → 判定近似重复
  3. 聚类：互相雷同的页面聚成一组
  4. 选代表：组里挑一个进索引、参与排名
  5. 其余折叠：剩下的不进索引

它比的是「近似」，不是逐字 —— 换语序、换同义词、调段落顺序都躲不掉。

认知修正：雷同不会让你被扣分，是让你白做。做 3 个雷同页 = 花 3 份功夫，只有 1 份进索引。这是浪费，不是处罚。
升级成真惩罚的条件（满足其一）：① 规模——雷同页到几十上百个量级 → 站点级「抓取内容 / 门户页」判定 → 整站降权；② 意图——页面唯一目的是接搜索流量、对访客无独立价值 → doorway page。单产品 3–5 个变体页通常只是折叠；8 个产品 × 5 个变体 = 40 页就危险。

6.4 同一个查询，站内也会互相竞争

Google 对同一查询通常只给同一站点 1–2 个结果（站点多样性机制）。所以两个同义页面不是"两个都上"，而是抢同一个坑位——本来能排第 8 的页面，因为有个兄弟页面在竞争，可能双双掉到 15 开外。

可观察信号：GSC 查询词报告里，若多个相似 URL 轮流出现、每个展现量都很低，就是系统在它们之间犹豫。这时把内容合并到一个页面上，总展现通常不降反升。

6.5 三类页面，各自能赢什么查询

页面类型内容特征能排上什么词
纯汇总页一堆卡片，每卡一两句话只有品牌词、导航词
带长文的枢纽页卡片 + 选型正文 + 对比表 + FAQ品类词、"how to choose" 类
产品详情页一个产品讲透：参数 + 案例 + FAQ主词、规格词、交易词
关键：你搜到第一页的那些「汇总页」，其实都是后两种。它赢不是因为它是汇总页，而是因为内容量达到了详情页级别。
实证：pfc-engineering.com/active-harmonic-filter/（分类页形态，但每个系列带几百字独立描述）排在搜索结果第 3。

6.6 阿里国际站 vs Google：目标一样，机制相反

维度阿里国际站Google 独立站
排名靠什么关键词匹配 + 店铺行为分页面权威 + 全网比较
多发几个同义链接鼓励：多一个入口多一份流量自罚：权重 ÷N + 换皮页
反馈周期几天到几周，改标题就见效3–6 个月才看得出
流量归属租的：规则一改排名就掉自己的：域名权重会沉淀
做起来后怎么扩多开摊位：继续铺品铺词种树：内链带起新页
最重要的一条：别用阿里的节奏考核独立站。阿里改个标题几天见效；独立站 3–6 个月才看得出。第 2 个月没动静就判定"方向错了"是最常见的死法。
一句话区分：阿里 = 流量租赁 + 即时反馈；独立站 = 资产建设 + 延迟回报。

两者可互相喂养：独立站的技术文章和案例搬到阿里做内容营销；阿里发品继续用变体标题（平台鼓励），独立站绝不使用同一手法。

6.8 诚实边界：哪些是公开原理，哪些不是

  • 公开：PageRank 的传递模型（有原始论文）；用近似哈希做重复检测（Google 有相关专利）。
  • 不公开：相似度阈值的具体数值、当前是否仍用 PageRank、各信号占多大比重 —— Google 从不公开，没人知道确切数字。
所以这一整套是机制模型：用来判断方向（别建雷同页、内链要集中、别用阿里节奏考核）足够可靠；不要拿它当精确公式去算"我该建几个页面"。
