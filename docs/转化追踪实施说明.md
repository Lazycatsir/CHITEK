# 转化事件追踪 — 实施说明

> 实施日期：2026-09-14 ｜ 状态：代码已完成，待 GA4 / 百度后台配置

## 一、架构：一个统一层，两端分发

```
用户行为（点击/滚动/提交）
        ↓
public/assets/js/analytics.js   ← 全站唯一追踪层（事件委托，零侵入）
        ↓
   ┌────────────┴─────────────┐
   │                          │
GA4（en/es/pt/ar）        百度统计（zh）
window.chitekTrack()       _hmt.push(_trackEvent)
```

- `window.chitekTrack(name, params)` 是统一入口，内部自动判断语种分发到 GA4 或百度，业务代码不用关心。
- 中文站不加载 GA4（大陆被墙 + PIPL），走百度统计事件；其余四语走 GA4。
- 脚本用 `<script is:inline src="/assets/js/analytics.js" defer>` 全站加载，**不被打包**，改这一个文件全站生效。

## 二、事件清单（最终版）

| 事件名 | 触发 | 主要参数 | 是否关键事件 |
|--------|------|----------|--------------|
| `generate_lead` | 联系表单提交成功 | form_type, product_type, country, industry, has_phone, utm_source/medium/campaign | ✅ 主转化 |
| `contact_click` | 点击电话 / 邮箱 / WhatsApp | contact_method(phone\|email\|whatsapp), page_path | ✅ 次转化 |
| `download_resource` | 下载 PDF/图纸等 | file_name, page_path | 普通 |
| `outbound_click` | 点击站外链接 | link_domain, link_url | 普通 |
| `form_start` | 首次聚焦表单任一字段 | form_type | 普通（算表单摩擦率） |
| `scroll_90` | 滚动到页面 90% | page_path | 普通 |
| `view_product` | 到达产品详情页 | product_name, page_path | 普通 |

> 原计划里 click_tel / click_email / click_whatsapp 三个事件合并为 `contact_click` + `contact_method` 参数。
> 原因：GA4 对事件总数敏感（每属性 500 个上限），同性质事件合并成"事件 + 参数"是官方推荐做法，报表里按参数拆分一样能看。

### 为什么表单要改成 AJAX 提交

原来的 Netlify 原生提交会**跳转到 Netlify 的通用成功页**——用户离开网站，且 `gtag` 事件大概率在跳转中丢失（页面卸载时请求被取消）。

改成 fetch 提交后：
1. 事件在成功后发，100% 可靠；
2. 用户停留在站内，显示绿色成功提示（5 语）；
3. 失败自动降级回原生提交，线索不会丢。

提交地址是 `location.pathname`（当前路径）。netlify.toml 里子域名用的是 `status = 200` 的 rewrite（不是 301），POST 的 method 和 body 会原样转发到 `/<lang>/contact`，Netlify Forms 能正常接收。

### UTM / 归因

- 首次带 UTM 访问 → 存 `sessionStorage`（本次会话）+ `localStorage`（首次接触，保留 30 天）；
- 自动写入表单隐藏字段 `attr_*`，**随表单一起提交给 Netlify**——销售收到的通知邮件里能直接看到客户从哪个渠道、哪个词、哪个落地页进来；
- `generate_lead` 事件也会带 utm_source / utm_medium / utm_campaign。

B2B 决策周期长，30 天首次接触归因比默认的"末次点击"更有参考价值。

### 3.1 配置区 —— 站点改版时只改这里

`analytics.js` 顶部有一个 `CONFIG` 对象，把所有跟站点结构相关的东西集中管理，改版时改配置而不是改逻辑：

| 配置项 | 当前值 | 什么时候需要改 |
|--------|--------|----------------|
| `siteDomain` | `'chitek-inno.com'` | 换域名 / 加区域站。**留空字符串会自动从 hostname 推导**（`en.chitek-inno.com` → `chitek-inno.com`） |
| `downloadExt` | pdf, zip, rar, 7z, dwg, dxf, step, stp, xls/xlsx, doc/docx, ppt/pptx | 资源中心上线后按实际格式补 |
| `productPathRe` | `/\/products\/.+/` | 产品页 URL 规则变了 |
| `scrollDepth` | `0.9` | 一般不动 |
| `firstTouchDays` | `30` | 想调整归因窗口（已实现真实过期清理） |
| `whatsappRe` | `wa.me` / `api.whatsapp.com` / `web.whatsapp` | 换 IM 渠道 |
| `submitEndpoint` | `null`（= 当前路径） | 换掉 Netlify 或改表单处理地址 |
| `debugParam` | `debug_track` | 一般不动 |

**域名判断已可配置化**：原来外链判断是 `host.indexOf('chitek-inno.com') === -1` 写死在事件逻辑里，现在改为 `isInternalHost(host)`——同时比对 `location.hostname`（当前站点）和主域名后缀（所有子域），换域名只改 `siteDomain` 一行。

### 3.2 改版同步检查清单

网站大改后逐项确认，否则追踪会静默失效：

| # | 检查项 | 不做的后果 |
|---|--------|-----------|
| 1 | 新模板保留 `data-lead-form` / `[data-utm-fields]` / `[data-form-success]` | 表单退回"提交后跳走"，事件丢失 |
| 2 | 产品页加 `data-product-name` 属性 | `product_name` 会取 h1，带上标题后缀不好看 |
| 3 | 产品页 URL 是否仍匹配 `productPathRe` | `view_product` 不触发 |
| 4 | 下载文件格式是否在 `downloadExt` 里 | 资源中心的下载不算转化 |
| 5 | 表单是否仍是 Netlify + 200 rewrite | 提交失败，需改 `submitEndpoint` |
| 6 | 中文站是否仍只走百度统计 | 若中文站要加 GA4，需改 `track()` 的分发分支 |
| 7 | **事件名和参数名不要改** | 改了要在 GA4 重新注册维度，且**历史数据不回溯** |

## 四、GA4 后台要做的事（一次性，约 15 分钟）

1. **标记关键事件**
   管理 → 事件 → 把 `generate_lead`、`contact_click` 右侧「标记为关键事件」打开。
2. **注册自定义维度**（否则参数只能在实时报告里看）
   管理 → 自定义定义 → 创建自定义维度：
   - `contact_method`（范围：事件）
   - `product_type`
   - `country`
   - `industry`
   - `utm_campaign`
   - `file_name`
   - `link_domain`
   每个维度上限 50 个字符，事件参数名要完全一致。
3. **建转化漏斗**（探索 → 漏斗探索）
   步骤：`session_start` → `view_product` → `form_start` → `generate_lead`
4. **加 UTM 来源报表**（探索 → 自由形式）
   维度：会话来源/媒介、着陆页；指标：会话数、关键事件数、转化率
5. **关联 Google Ads**（如果有投广告）：管理 → 产品链接 → Google Ads 关联

## 五、百度统计后台要做的事（中文站）

1. 百度统计 → 事件转化 → 新增事件，类别填 `Conversion`，动作填 `generate_lead` / `contact_click` / `download_resource`；
2. `_hmt.push(['_trackEvent', 'Conversion', name, path])` 已在代码里按这个格式发送，动作名要与后台配置一致；
3. 完成营业执照实名后事件数据才会正常入库。

## 六、怎么验证

1. 本地/线上任意页面加 `?debug_track=1`，打开控制台，所有事件会打印 `[chitek.track] 事件名 参数`；
2. GA4 → 实时报告 → 事件计数，点电话/邮箱应立刻看到 `contact_click`；
3. 提交一次测试表单 → 应看到 `generate_lead`，且页面出现绿色成功提示、按钮变灰；
4. 检查 Netlify → Forms → contact，应收到一条新记录，字段里带 `attr_utm_source` 等；
5. 销售邮箱应收到表单通知（含全部字段与归因）。

## 七、已知边界

- 广告拦截器 / 隐私模式会拦掉 gtag，事件数会少于真实询盘——**以 Netlify Forms 的记录数为准对账**，GA4 看趋势和渠道占比。
- 百度统计事件有约 5–10 分钟延迟。
- 中文站没有 GA4，所有中文站转化以百度统计 + Netlify 表单为准。

## 八、后续可选增强（按性价比排序）

1. **GA4 Measurement Protocol 服务端上报**：表单提交后由 Netlify Function 服务端发 `generate_lead`，彻底免疫广告拦截（需 measurement_id + api_secret）。
2. **Netlify Function 转发到 CRM / 企业微信机器人**：线索实时推送销售群。
3. **WhatsApp 点击带参数**：`wa.me/<号码>?text=...` 预填咨询内容，提高转化。
4. **沉淀到 Looker Studio**：GA4 + GSC 数据合并出月度自动报表。
