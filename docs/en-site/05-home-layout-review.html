一、范围与现状基线

按页面源码顺序：Hero（排除）→ Customer Favorites / #featured-products（排除）→ ABOUT → Product Series → Solution Insights → Latest News。本次只评后 4 段。Footer 由 BaseLayout.astro 全站共用，不纳入首页整改。

结论：这 4 段的问题不是「某处不好看」，而是三件底层的事没定下来 —— 内容宽度没有统一（同一页出现 72px 与 115.2px 两套左边界）、区块边界没有建立（白底连片 + 间距压到 112px + 满屏撑高混用）、桌面端把卡片的核心信息藏了（案例标题与摘要默认不可见）。建议先做 P0 这四条四两拨千斤的修正，P1 一次性回归，视觉风格类的 P2 往后排。

二、P0 —— 先做：可见性与可信度，不动结构

P0-1　恢复 Solution Insights 卡片的可读性

现状11-10 起，桌面 ≥768px 下 .insight-heading（橙色案例标题）与 .insight-desc 默认 opacity:0，仅 hover / focus-within 淡入。结果是三张大图 + 三个「Read the … case」链接，用户不知道每张图是哪个案例。

问题卡片的「身份信息」被当成装饰藏掉了。hover 只能承载补充说明，不能承载「这是什么」——尤其鼠标还没移上去时，三张卡互相无法区分（视觉层级倒置：次要的链接比主标题更显眼）。另外触控虽已做常显，但桌面触屏 / 笔电触控板用户仍会踩到。

建议折中方案，二选一由你裁决：A 标题常显、描述保留 hover（信息层级回来了，干净度基本保留，改动最小）；B 标题与描述都常显，把描述压到 2 行 line-clamp-2 控制卡片高度。不建议维持现状。

验收1440 视口、不触发任何 hover 时，3 张卡的案例标题 computed opacity = 1；390 视口仍全部常显；卡片高度在 hover 前后不变（不跳版）。

P0-2　「Play Video」名实不符

现状ABOUT 区唯一的主按钮是橙色实心 + 播放三角图标，文案 Play Video，但 href 指向 /about，点进去是普通关于页，没有视频。

问题图标和文案是在给一个承诺（点开会播放），实际行为是跳转——这叫 affordance 失真，B2B 站点上很伤信任感。而且它占据了整段最重的视觉权重，却不是转化动作。

建议要么把文案改成 About CHITEK / Our Story 并把三角换成右箭头；要么真接一个视频弹层（需你确认有无成片）。前者零成本，建议先做。

验收按钮文案与落地页一致，无播放语义的图标；控制台无死链。

P0-3　卡片内容默认可见（渐进增强）

现状.fade-up、.ps-card、.insight-card、.news-card 默认都是 opacity:0 / 位移，靠 JS 的 IntersectionObserver 加 .visible 才显现。

问题JS 一旦没跑起来（脚本报错、被拦截、爬虫渲染、弱网下脚本超时），这 4 段会大面积空白。文字虽在 DOM 里，但视觉呈现是空的。站里已经按「SSR + 渐进增强验两层」的口径做过验证，这一层目前是反过来的。

建议把「隐藏」收敛到一个开关：由 BaseLayout 在 <html> 上挂 js class，CSS 写成 .js .ps-card { opacity:0 }。没有 JS 时内容全部常态可见，动画只是增强。

验收禁用 JavaScript 加载 /en/，ABOUT 大框、Product Series 标题与 6 卡、3 张案例卡、3 张新闻卡全部 opacity = 1 且位置正常。

P0-4　补一个主转化入口

现状这 4 段里的可点元素全是「导航型」：All Products / Series → / Read the case / View all news。整页从 ABOUT 滚到 NEWS 结束，没有一处 Get a Quote / Contact Sales / Download Catalog，然后直接进 Footer。

问题B2B 首页的收尾缺「下一步做什么」。用户看完案例和数据后意向最高，却没有承接动作，转化全靠用户自己去 Nav 找 Contact。

建议在 #news 之后、Footer 之前加一条轻量 CTA 条（一句话价值主张 + 一个主按钮 + 一个次按钮），高度控制在 160px 内，不新增大区块。属新增区块，需你裁决是否加。

验收1440 / 390 两视口下 CTA 条可见、主按钮可点、无横向溢出。

三、P1 —— 结构性整改，建议一次性做完再回归

P1-1　统一内容宽度（栅格对齐）

现状ABOUT 用 w-[clamp(320px,90vw,1800px)] mx-auto → 1440 下左边界 72px；其余三段用 px-[clamp(24px,8vw,160px)]（+ max-w-[1320px]）→ 左边界 115.2px。滚动时内容左右边缘错开 43.2px，深色区到浅色区的切换会明显「晃一下」。

问题同一页出现两套容器系统；而且 ABOUT 的 1296px 容器比父级可用宽度（1209.6px）还宽 86px，靠 body { overflow-x-hidden } 兜住——这也是阿语 RTL 下既有 1486/1440 横向溢出的来源之一。

建议四段统一到一套：px-[clamp(24px,8vw,160px)] + 内层 max-w-[1320px] mx-auto w-full。ABOUT 去掉 90vw 容器。

验收1440 下四段内容左边界相同（±1px）；390 下无横向溢出；5 语首页 + 阿语 RTL 一并回归（既有溢出单列跟踪，不算本次引入）。

P1-2　取消「按屏幕高度撑满」，改成按内容定高

现状#about 与 #products 都用 min-h-[calc(100vh-72px)]；而 11-10 已把 #solutions 的 min-height 覆盖成 0、#news 上内边距压到 20px。结果是前两段「满屏」、后两段「贴内容」，节奏在页面中间突然变档。

问题区块高度跟屏幕高度绑定而不是跟内容绑定：900 高屏留白约 180px，1080 高屏留白会更大，不同设备看到的疏密完全不同。而且 min-h 写在 class 上、又被 style 里的 ID 选择器覆盖，维护时容易误判。

建议四段统一改成内容高度 + 固定上下内边距（建议 py-[clamp(64px,7vw,112px)]），删掉两处 min-h-[calc(...)] 与 11-10 的 #solutions{min-height:0} 补丁。深浅节奏靠背景交替建立，不靠空白硬撑。

验收1440×900 与 1440×1080 两档下，每段上下留白数值一致；四段总高度变化在预期内；无跳动。

P1-3　Product Series 的 tab 状态只切了一半

现状点击 Active Harmonic Filter / Static Var Generator 两个 tab，JS 只切换左侧介绍文字和右侧产品图；中间 6 张特性卡完全不变，且文案含 AHF 专属口径（efficiency up to 98.5–99.2% 等）。另外 tab 是 <div class="tab">，无 role="tab" / aria-selected / 键盘焦点。

问题控件承诺了「换一个产品」，但只兑现了三分之一，用户会误把 AHF 参数当成 SVG 参数（状态一致性问题）。<div> 当按钮也违反站内「功能控件一律 <button type="button">」的硬规则，键盘用户根本切不了。

建议二选一：A 6 张卡跟着 tab 一起切（数据化，改动较大）；B 把中间网格明确改叫「共通技术底座 / Platform Capabilities」，去掉产品特指措辞，让它与 tab 解耦（改动小，推荐）。无论哪种，tab 都换成 <button type="button" role="tab" aria-selected> 并支持左右方向键。

验收切到 SVG 后中间网格无 AHF 专属数值（选 B）；Tab 键可聚焦两个 tab、Enter/方向键可切换；SSR 输出里两个 tab 都存在。

P1-4　给 Solutions 与 News 之间建立分组边界

现状11-10 之后两段同为白底，间距压到约 112px（原 368px 的 1/3）；上面是 3 张满幅图片卡（rounded-2xl），下面是 3 张白底细边框卡（rounded-2xl）。

问题同底色 + 近间距 + 同样三列，按接近原则会被读成「一个 6 卡网格」，但两组卡形态又不一样，于是显得杂乱——这是分组失效而不是间距不够。另：白底上的白卡只靠 1px 细边框分层，层次很弱（11-10 已提示过）。

建议不改 11-10 定的紧凑间距，改用两招建立边界：① 给 #news 一句居中的分组引导语（如 From the blog 之类），把两个 H2 的层级关系讲清楚；② 新闻卡底色改极浅灰 #fafafa 或加一条 1px 顶分隔线。「白底同色」是 11-10 刚定的口径，是否允许浅灰分隔需你裁决。

验收1440 下两段视觉上可明确区分为两组；卡片层次可辨；间距仍约 112px（不回退）。

四、P2 —— 设计系统收敛，可排到后面

P2-1　圆角语言统一

现状同一页并存三套：rounded-[2px]（箭头按钮 / All Products）、rounded-2xl = 16px（案例卡 / 新闻卡）、rounded-full（View all news）。

建议定一档主圆角（工业设备类建议 4px，克制、偏硬朗；若要柔和则统一 12px），按钮类单独一档并 token 化。不要靠胶囊按钮来做「主次区分」，用色彩和尺寸区分。

P2-2　字号阶梯按「用途」定义，不急着拉平数值

现状11-10 等比降 12% 后，H2 是 25.2 / 40 / 42 三档（Customer Favorites / ABOUT / 三个居中标题），正文散布 10～16px 多档 clamp。

建议先定义三档的用途（区块大标题 / 深色区内嵌标题 / 卡片组标题），把「为什么不一样」写进规范；再决定是否统一数值。11-10 明确「保持各自相对大小、没强行拉平」，属你刚定的口径，这里只登记问题，不擅自改。

P2-3　ABOUT 的证据信息去重、补口径

现状深色区里先是一组 2×2 四宫格（60% / 自主设计 / 产品多样 / 品质保障），下面又是一排 4 个统计数字（2019 / 2700+ / 30+ / 20+），两组「四列证据」连着出现；30+ Intellectual Properties 与四宫格里的「More than 30 Intellectual Properties」重复；60% 没有说明是什么的 60%。

建议四宫格改成纯「能力标签」（去掉数字），硬数字只留在统计条；60% 补完整口径（如 60% of staff in R&D）或删掉。B2B 采购看数字会追问来源，悬空数字不如不写。

P2-4　动效收敛为一套

现状4 套入场动画并存（fade-up 上移、左右 conv-left/right 各 64px、标题从左 64px、卡片 36/48/64px 三档错峰），且进出视口会反复重播。

建议统一成一套：仅 opacity + 8px 上移、只首次进入触发、同组错峰 ≤80ms。prefers-reduced-motion 已处理，保留。滚回来重播对阅读是干扰，不是惊喜。

五、依赖关系

  • P1-1 与 P1-2 必须一起改：容器和区块高度都影响整页垂直节奏，分两次做会各回归一遍；改完统一跑一次 5 语回归。
  • P0-1 / P1-4 卡在口径裁决上：都是 11-10 刚定的口径，先定再动。
  • P0-4 是新增区块：需先定「加不加」，加的话排在 P1 之后，避免 CTA 条跟着容器改动再挪一次。
  • P2 四项彼此独立，也不依赖 P0/P1，可任意排期。

六、验收清单（只测 1440 与 390 两个视口）

  1. 四段内容左边界数值相同（±1px）。
  2. Solutions 与 News 视觉上能明确区分成两组，间距仍约 112px。
  3. 桌面不 hover 时，3 张案例卡的标题可见；hover 前后卡片高度不变。
  4. 禁用 JS 后，ABOUT 大框 / Product Series 6 卡 / 3 张案例卡 / 3 张新闻卡全部可见。
  5. 切到 SVG tab 后，中间网格无 AHF 专属参数（或已明确标为共通能力）。
  6. Tab 键能聚焦并切换两个 tab；按钮有 type="button"。
  7. 1440 / 390 无横向溢出；5 语 H1、H2 与统计数字字号不变（不回退 11-10 口径）。
  8. 阿语 RTL 既有 scrollWidth 1486 / 1440 溢出单列跟踪，不算本次回归项。

七、待你裁决（不自己拍板）

  1. P0-1：案例标题是否改回桌面常显（A 只放标题 / B 标题+描述都常显 / 维持现状）。
  2. P1-4：News 白底是否允许改极浅灰，或只加分隔线 + 引导语。
  3. P0-4：是否在 News 后新增一条主转化 CTA 条。
  4. P1-3：中间 6 卡跟 tab 一起切（A），还是改成「共通技术底座」与 tab 解耦（B，推荐）。
  5. P2-2：H2 三档字号是否统一（11-10 已定「保持相对大小」）。
  6. 范围外单列：Footer 三个栏目名仍是 <h4> 造成 H2→H4 跳级（P0-2 待裁决项），属全站组件，不在本次首页整改内。
