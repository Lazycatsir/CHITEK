第一部分 · 算法层：三套逻辑在评什么

操作规则是算法的推论。先看懂在评什么，清单就不用背。

一句话概括三者的分歧：Google 赌「语义」，Bing 赌「分发」，生成式引擎赌「可被切走」。

分工：Google 拿流量，Bing 拿企业客户，生成式引擎拿品牌认知。三条腿都要，但投入不成比例——Bing 的增量成本最小。

1.1 三套核心算法：各自在评什么

GoogleBing生成式引擎
质量框架E-E-A-T + YMYL相关性 / 质量与可信度 / 用户参与度 / 新鲜度 / 位置RAG 重排：相关性 + 信息密度 + 可验证性

失败方式排名下降收录不进 / 排名下降直接不被引用（无声）

⚠️ 三者的失败方式不同，这是最容易被忽略的一点。 Google 和 Bing 的失败是「排名掉了，还能查得到」；生成式引擎的失败是「AI 根本没提你」，而且你不会收到任何通知。这就是为什么做 GEO 必须先建基线测量——否则连自己失败都不知道。

1.2 抓取层：各引擎实际读的是哪一份 HTML

算法再聪明，也只在它收到的那些字节上工作。而三者收到的字节并不一样：

Google（含 AI Overviews / Gemini）Bing（含 Copilot / ChatGPT 候选池）AI 爬虫（GPTBot / ClaudeBot / PerplexityBot…）
索引基准移动版（移动优先）两端都看（设备无关单一索引）不区分端（没有视口这个概念）
抓取器Googlebot SmartphoneBingbot（桌面 / 移动两个 UA，robots.txt 不区分）纯 HTTP GET，无渲染器
JS 渲染渲染（二次渲染，与首次抓取可能隔数秒到数周）渲染（Chromium 版 Edge 内核），但官方建议重要内容别只靠 JS不渲染
实际读到的移动版 DOM桌面 + 移动落在同一个索引里服务器返回的原始 HTML

⚠️ 三条必须纠正的直觉：

  • Bing 不是移动优先。 Google 2023-10 完成 mobile-first indexing，Bing 没有跟进——它维持一个设备无关（device-agnostic）的单一索引。微软 Bing 的 James Murray 原话是「we think it's more useful to have an integrated view and to be more device agnostic」。网上（尤其 AI 生成的内容农场）说「Bing 已转向 mobile-first」是错的。含义：桌面端与移动端的内容对 Bing 同等重要，不存在「移动版写全了就够」。
  • AI 爬虫根本没有「端」。 GPTBot / ClaudeBot / PerplexityBot / OAI-SearchBot 等都是纯 HTTP 客户端，不执行 JS（Vercel 2024-12 实测：GPTBot 抓取了 11.5% 的 JS 文件、执行了 0 行）。它们读到的只有服务器直出的那份 HTML。
  • 例外只有两家：Google-Extended（Gemini 用）与 Applebot 会渲染 JS，因为它们共用 Googlebot 的渲染服务。所以「Gemini 看得到」不等于「ChatGPT 也看得到」——同一份页面，四家引擎看到的可能不是同一个东西。

⚠️ 一条最隐蔽的传导链：ChatGPT 搜索的候选页面来自 Bing 索引（Bingbot 会渲染 → 纯前端渲染的站也能进候选池），但回答时 OAI-SearchBot 现场抓取、不渲染 → 结果是「排名在、引用里没有」。

推论：真正决定可见性的不是「渲染得多漂亮」，而是内容在初始 HTML 里存不存在。SSR / 预渲染的站点天然同时满足三方；纯客户端渲染的站，会在 Google 移动优先、Bing 设备无关、AI 引用三处同时出问题。Google 移动优先的细节见 §2.1，爬虫放行清单见 §18.1。

1.3 算法哲学的分歧：它解释了一切差异

  • Google 二十年的主线是更强的语义理解：从 PageRank 到 RankBrain、BERT、MUM，目标是「即使你表达模糊，我也猜对你要什么」。所以它对关键词的字面形式越来越宽容。
  • Bing 的主线是默认位：Windows、Edge、M365、Xbox。它的份额不来自用户偏好，而来自分发结构。所以它的排序更忠实于字面信号，也更看重域名的整体声誉——因为在企业环境里，用户信任的是「这个站靠不靠得住」，而不是逐页判断。

理解这条分歧，很多现象就不用背了：为什么 Bing 上精确匹配词权重更高？为什么 .edu / .gov 外链在 Bing 更吃香？为什么 LinkedIn 在 Bing 有用而在 Google 基本无效？——全都是「分发 + 字面 + 机构声誉」这条主线的自然结果。

2. Google 的底层

2.1 先决条件：Google 索引的是移动版

2023-10 Google 完成 mobile-first indexing，2024-07-05 起桌面版 Googlebot 完全不再参与索引（仅存在于少数验证场景）。含义只有一句：Google 索引里存的那份 HTML，是 Googlebot Smartphone 在手机上渲染出来的那一版。 桌面版写得再多，只要移动版没给，Google 就等于没看见。

⚠️ 它改变的是「优化对象」的定义——我们要优化的不是「自己写的那份源码」，而是「Googlebot Smartphone 渲染出的那份 HTML」。三条推论直接落到操作上：

  • 内容对等，缺一即无。 移动版没有输出的正文 / 图片 / schema 等于不存在；桌面端多出来的那部分，写了也不产生 SEO 收益。
  • 折叠可以，「点击才加载」不行。 tab / accordion 里的文字只要在 HTML 标记里，Google 照常收录（本站案例 tab、决策树「初始全展示」正是按此设计）；「点击后才用 JS 拉取」的内容渲染器不会去取——那才是真的丢内容。
  • 别在桌面端下重注。 桌面专属的大动效、hover 交互、更炫的排版不产生任何 SEO 收益。桌面流量当然还在（StatCounter 2026-07：欧洲桌面浏览量 51.8%、北美 52.6%），体验该做——只是它不在 SEO 的考核集里。

两条同源结论：内链必须是移动版 DOM 里真实存在的链接（汉堡菜单用 CSS 隐藏没问题，用 JS 动态生成菜单就不行）；canonical / hreflang / JSON-LD 必须出现在移动版 HTML 里（本站全站 SSR 输出、与视口无关，天然满足——但任何「按断点条件注入」的写法都会让它们直接消失）。Core Web Vitals 同理，只按移动端测（LCP < 2.5s / INP < 200ms / CLS < 0.1）：桌面 95 分、移动 55 分，在 Google 眼里就是一个 55 分的站。

2.2 E-E-A-T 与 YMYL

E-E-A-T（Experience / Expertise / Authoritativeness / Trustworthiness）是 Google《搜索质量评估指南》里的质量框架，写给人工评估员用；Google 用可计算的代理指标去近似它。所以它无法被「技术性优化」，只能真的做到，并让它可见。

维度一句话官网的落地载体
Trust 信任你是不是真实存在、说话算数的公司真实联系方式与地址、质保条款、证书编号可核验、隐私政策
Experience 经验你做过，不只是知道项目案例（行业 + 国家 + 规模 + 实测数字）、现场照片、调试记录
Expertise 专业参数、原理、标准讲得对且具体完整参数表、datasheet、选型指南、接线图、标准符合性
Authority 权威别人怎么看你第三方认证、专利、协会会员、行业媒体引用

次序不能反：Trust 是地基，Experience 是差异，Expertise 是弹药，Authority 是结果。 把力气全花在 Authority（到处发外链），落地页却连公司地址都查不到——这是把顺序做反了。

为什么 Experience 最值钱：2022 年底 Google 在 E-A-T 前加第一个 E，背景正是 AI 内容泛滥。AI 写得出「谐波会导致变压器过热」，写不出「某钢厂 40MW 项目 THD 从 14% 降到 2.8%，用了 3 台 300A」。这个差距就是工业品官网的护城河。

YMYL（Your Money or Your Life）是 E-E-A-T 的放大器。 涉及健康、财务、人身安全的题材，Google 会用更严的标准衡量。

⚠️ 这一点与我们直接相关：工业电力设备（谐波治理、无功补偿）属于涉及电气安全的品类，处在 YMYL 邻域。含义有三条：

  • 参数不能错、认证不能虚、案例不能编——错误在本品类的代价被放大
  • 越具体的可核验信息（标准号、认证编号、实测数据），价值越高
  • 泛泛的营销文案在本品类里几乎不起作用

反过来看这是好消息：工业品天然是 E-E-A-T 友好的赛道——真正做这行的公司本来就有真东西，只要把它展示出来就赢过大部分人。

2.4 PageRank 还在，但换了角色

外链仍然是信任投票，只是权重相对于「内容质量 + 实体清晰度 + 用户满意度」已经下降。今天的外链价值次序大致是：

行业媒体 / 协会 / 标准机构引用  >  客户与合作伙伴站  >  行业目录  >  自建站群（禁止）

3. Bing 的底层

3.1 为什么值得做

① Bing 索引就是 Copilot 的底层，而 Copilot 覆盖五个触点

Bing 搜索 / Edge 侧栏 / Windows 11 / Microsoft 365（Word、Excel、Outlook、PowerPoint）/ Teams——全部拉同一个 Bing 索引。优化一次，五个入口通吃。Bing 同时是 ChatGPT Search 的主要检索源之一（两者引用重叠度很高）。

② 用户画像与工业品高度匹配

企业环境中 Microsoft 365 占比常达 60~80%，制造业与受监管行业更高。这正是工业品的工程与采购决策人群。

③ 份额要拆开看：桌面才是关键

Bing 的桌面份额约为移动端的 15 倍——因为它的份额来自 Edge / Windows 的默认位与企业标准化，不是用户主动选择。

④ 但要把两种价值分开算

  • Bing 的「搜索流量价值」：分市场差异极大。北美 / 日本 / 澳新 → 值得；欧洲 → 中等；拉美 / 印度 / 非洲 / 中东 → 传统流量有限。
  • Bing 的「索引价值」：不受份额限制。Copilot 是通过 M365 订阅触达企业员工的，不是通过「某个国家的 Bing 搜索用户」。一个巴西工程师用 M365 Copilot 提问，照样去 Bing 索引里找。

所以对工业品来说，Bing 的主要价值不是「多 5% 自然流量」，而是它是 AI 可见性的入场券——不做 Bing 等于放弃 Copilot 和一部分 ChatGPT。

⑤ 竞争度极低：绝大多数同行只盯 Google。

3.2 官方五要素（Bing 的底层算法）

Bing 的 Webmaster Guidelines 把排序依据归纳为五条：

要素含义
Relevance 相关性页面与查询的匹配程度
Quality & Credibility 质量与可信度内容质量、站点声誉、作者可辨识
User Engagement 用户参与度点击率、停留、回访等交互信号
Freshness 新鲜度内容是否新鲜、是否持续更新
Location 位置地域相关性

⚠️ 「User Engagement」和「Location」是 Bing 官方明确列出、而 Google 从不强调的维度。 这就是「Bing 更依赖交互数据」的出处——历史上 Bing Toolbar 提供了大量真实用户行为样本。

3.3 三个可操作的推论

  1. 字面 > 语义。 主要关键词在 title / H1 / URL 里用精确形式，不要用同义改写把它替掉。（在 Google 那里无所谓，在 Bing 这里有差别。）
  2. 域名级声誉 > 单页质量。 与其死磨一页，不如保证整个域看起来是一家真实、持续经营的公司——完整 About、真实地址与联系方式、一致的品牌名。
  3. 机构背书 > 个人背书。 .edu / .gov / 协会 / 行业媒体 的外链在 Bing 加成更明显；LinkedIn 是微软自家资产，其信号被计入，公司页要完整。

3.4 Bing 独有的两个机制

① IndexNow —— 即时收录

Bing 联合开发的开放协议：发布或更新后主动推送 URL，分钟级进入索引，不必等爬虫发现。支持 Bing / Yandex / Naver / Seznam / Yep。Google 不支持。

价值不在「快」本身，而在：第一个被索引的页面往往成为该话题的「种子来源」，后续引用会向它集中。晚两天，等于把位置让给竞品。

② Bing Webmaster Tools 的 AI Performance Report

目前唯一由搜索引擎官方提供的 AI 引用追踪报告——显示哪些查询触发了对你内容的 Copilot 引用、带来多少曝光与点击、以及匹配到的底层意图。Google Search Console 没有对应功能。

3.5 Copilot 的 grounding 链

Copilot 的答案 = Bing 索引检索 + LLM 合成 + 引用标注。

所以对 Copilot 来说，排名不是目标，进入检索候选才是：

① 页面在 Bing 索引里         ← 不是「Google 排得好」，是「Bing 收没收录」
      ↓
② 内容能被切成可用段落
      ↓
③ 被 Copilot 选取并标注来源

⚠️ 第一环断掉，后面全部无从谈起。

4. 生成式引擎的底层（GEO）

4.1 技术栈：RAG 四阶段

生成式引擎不是「更聪明的搜索」。它的内部是这样跑的：

① 查询理解与扩展
   把你的问题拆成多个子查询（query fan-out），并行去检索
        ↓
② 检索（Recall）
   混合检索：稀疏（关键词 / BM25）+ 稠密（向量语义）
   从索引里召回一批候选【段落】，不是整页
        ↓
③ 重排（Rerank）★ 最关键的一层
   用交叉编码器给每个候选段落打分，按「能否回答这个问题」排序
        ↓
④ 生成与引用
   LLM 只基于被选中的段落合成答案，并标注来源

4.2 从这套栈推出的四条结论

① 优化单位是「段落」，不是「页面」。 检索召回的是 chunk、重排打分的是 chunk、生成引用的是 chunk。页面写得再好，切不出好段落就等于不存在。

② 重排层是真正的战场。 能不能被召回只是入场券；能不能在重排里排进前列，才决定会不会被引用。重排打分看的是：

  • 与问题的直接相关性——这个段落是否独立回答了它
  • 信息密度——同样长度里事实更多者胜
  • 可验证性——有数字、有单位、有出处 ＞ 形容词
  • 来源可信度——域名与实体的声誉

③ query fan-out 意味着要覆盖「子问题」。 一个问题会被拆成多个子查询并行检索。所以一个页面覆盖的相关子问题越多，在多个子查询里被召回的概率越高——这正是「内容成网」在 GEO 里的技术解释。

④ 引用偏好「独占信息」。 AI 不会引用到处都能找到的常识。原创数据、实测结果、具体配置、行业特有的经验判断，才是被引用的理由。这也是官网案例页存在的真正意义。

4.3 可被引用的三种结构

GEO 不是「写得更好」，是把内容改成可被机器切走的形状：

  1. 答案块 —— 每个小节开头用 40~60 词给出完整答案，后面再展开理由。AI 抽的就是这一段。
  2. 数据块 —— 具体数字、标准号、参数、实测结果。含糊表述（「效果显著」）不会被引用，有出处的具体数字才会被引用。
  3. 对比块 —— 表格与并列结构。「A vs B」在 AI 查询里占比极高，有对比表的页面天然优先被抽取。

配套的可信度动作：引用外部权威来源（研究、标准、政府数据）、标注更新日期。

5. 三者共用的六条

前五条讲「内容该做成什么样」，第六条讲「内容该覆盖什么」。

  1. 可切块 —— 每个小节能独立回答一个问题
  2. 可验证 —— 具体数字、标准号、可核对的资证，而不是形容词
  3. 实体清晰 —— 品牌名 / 型号 / 公司信息全站一致，能被识别为同一个实体
  4. 有出处 —— 数据能溯源，观点有作者或机构
  5. 够新 —— 有更新日期，且真的在更新
  6. 流量矩阵 —— 覆盖买家的全部提问路径（见 §5.1）

这六条同时喂三套算法。为 GEO 做的最好的事，通常也是为 SEO 做的最好的事——不是两套工作，是一套内容在三种读法下都成立。

6. 四层骨架与权重流向

首页 ──────────── 品牌词，全站内链的源头
  ↓ ↑

7. URL 规范（已敲定，不再变）

页面数量与内容方向已冻结，URL 是这套骨架的地址，规则一并冻结。

  1. 全小写、连字符分词、无参数、无 ID、无日期
  2. 层级固定 /{lang}/{category}/{product}
  3. 型号 slug 全球统一用英文（型号本身全球通用）；品类 slug 可本地化——这是唯一值得本地化的部分
  4. 尾斜杠全站一致，不允许有的带有的不带
  5. 尽量短，但要能读出这是什么产品

变更纪律：URL 一旦上线只允许 301，且必须同步更新六处——漏一处就产生死链或重复内容。

18.1 先分清三个环节，再看谁在收你

⚠️ 抓取 ≠ 索引 ≠ 引用，是三个独立环节。任一环没过，结果都是「AI 的答案里没有你」。

抓取   内容能否被获取       ← 爬虫有没有被拦
  ↓
索引   内容能否被留下       ← 进了哪一家的索引
  ↓
引用   内容能否出现在答案里  ← 重排层有没有选中你

两个最常见的误判：

  • 访问日志里出现 AI 爬虫，不等于会被引用。 爬虫要分类看（见下）——训练类爬虫的到访与搜索可见度完全无关。
  • 在 Google 排得好，不等于 AI 找得到你。 各家用的不是同一个索引。

两家主流厂商都把爬虫拆成三种用途，可见度影响完全不同：

  • robots.txt 的 Allow: / 本身不拦它们，但CDN 的机器人防护与防火墙限流会悄悄拦掉——要实际验证返回 200 而不是 403

它一度被当作「AI 时代的 robots.txt」。但实践反馈是：主流引擎在抓取阶段直接抽取网页正文并转 Markdown，并不依赖 llms.txt 提供的索引路径——部署成本极低，但目前看不到实际收益。属于「做也无妨，别指望它」。

18.2 权重从哪来：GEO 的三层权重

传统 SEO 的「权重」约等于域名权威 + 外链。GEO 不是——它至少分三层，而且从下往上越来越难、越来越关键：

层决定什么怎么攒
① 索引层有没有资格被检索到进对索引（§18.1 五个）；技术可抓取
② 实体层AI「认识不认识」你这家公司预训练里的品牌认知 + 全站实体一致性
③ 证据层重排时凭什么选你第三方信源 + 独占数据 + 可切块结构

① 索引层是门槛，不是优势。 五个索引都进了才刚站上起跑线；这一层没做好，后面全部作废。

② 实体层最容易被忽略。 AI 有「主要偏差」——预训练阶段对品牌形成的先入之见。有研究提到一个具体现象：某些中国品牌即使在搜索结果里排第一，AI 也可能拒绝推荐。这不是内容问题，是认知问题，而且改不了——只能靠第三方的独立叙述去对冲：别人怎么介绍你，比你自己怎么说更重要。

所以实体层的做法是「一致性 + 外部复述」：品牌名 / 型号 / 公司信息在全站和所有外部渠道用同一个写法，让 AI 能把它归并到同一个实体上。

③ 证据层才是重排层的战场（§4.2）。拼三件事：有没有第三方的独立叙述、有没有别人没有的数据、段落能不能被整块切走。

⚠️ 一句反直觉但很关键的判断：研究显示 AI 答案对第三方信源的依赖度约 95%——品牌自有域名的引用占比，Google AI Overviews 约 59.8%、ChatGPT 约 44.7%、Perplexity 约 28.9%。

也就是说：只做官网，在 AI 的答案体系里最多只能拿到一半存在感，而 Perplexity 那边连三成都不到。「内容发在哪里」和「内容是什么」同等重要。

18.3 第三方引用：AI 最看重的站外信号

AI 不会引用「自己夸自己」的内容——它需要一个独立理由相信你。

  • 社区平台（Reddit、Quora、行业论坛、Stack Exchange）在 AI 引用中占比极高：真实的技术回答比官网文案更容易被引用
  • 「最佳 XX 厂商」类的第三方汇总文章
  • 行业评测平台、协会目录、企业档案
  • LinkedIn 上的专业讨论（同时也喂 Bing）
  • 维基百科 / 知识面板（若适用）

所以 GEO 有一半工作在站外。 一个在技术社区里认真回答问题的工程师，带来的 AI 引用可能超过十篇官网文章。

18.4 多语言 GEO：一个被忽略的机会

同一个品牌在不同语种里的 AI 可见性是彼此独立的。 英文里被频繁引用，不代表西班牙语或阿拉伯语里也能被找到——各语种的训练数据与检索语料完全不同。

  • 五语站点的每一语，都是独立的一次 GEO 机会
  • 西语 / 葡语 / 阿语市场的 AI 引用竞争远低于英文，同一份内容本地化后，被引用的概率显著更高
  • 但只有被索引、且能切块的本地化内容才算数；机器翻译的潦草版本既不被引用，也不被信任

18.5 GEO 与 SEO 的关系

不是替代，是叠加。 RAG 的第一步是检索，检索依赖索引——SEO 是 GEO 的地基。

但有一个反转值得记住：AI 概览让点击变少，却让「品牌被记住」变重要。客户可能不点你的链接、直接问 AI，然后记住品牌名再来搜你。所以 GEO 的收益，往往先在品牌词搜索量上体现，而不是在自然流量报表里。

指标含义

GEO 站外篇（CHITEK）

2026-09-29 立。SEO_GEO_FRAMEWORK.md 的站外分册——那本讲「站内怎么改」，这本讲「站外怎么做、权重才高」。

0. 一句话

站内决定「AI 能不能把你的话切走」，站外决定「AI 愿不愿意说你的名字」。

而后者的份量远超想象：84% 的 AI 引用来自 earned media（第三方赢得的内容），95% 的答案依赖第三方信源。自有域名能拿到的引用占比——Google AI Overviews 约 59.8%、ChatGPT 约 44.7%、Perplexity 约 28.9%。

只做官网，最多拿到一半存在感；Perplexity 那边连三成都不到。

⚠️ 但这个比例取决于查询类型（三组研究口径不一，实为同一件事的三面）：

查询类型引用结构
品牌词查询（「CHITEK 怎么样」）官网权重高（Trustmary 测得官方域名约 62%）
泛需求查询（「AHF 怎么选」）第三方主导——评测、论坛、数据服务

所以「95% 依赖第三方」要按这个前提理解：客户在还没听说过你的时候，看到的基本都是别人说的话。

1. 提及 ≠ 引用：两个指标，两套做法

指标定义价值
提及（Mention）AI 在答案里说出你的品牌名品牌认知
引用（Citation）AI 把你的页面当作来源列进脚注，用户可点可查流量 + 可信度

⚠️ 高引用、低提及 = AI 在白嫖你的内容（用了你的数据，不给你署名）。两个指标必须分开记——只看其中一个一定会被误导。

1.1 它们要的东西完全不同

引用（Citation）提及（Mention）
目标让 AI 把你的页面当来源让 AI 说出你的品牌名
载体页面 / 段落实体认知（跟页面无关）
靠什么内容可切块 + 独占数据第三方独立叙述
谁控制你自己（站内工程）别人（站外经营）
见效2–4 周以季度计
失败的信号数据被用了，但没署名AI 推荐同类产品时完全没想到你

一句话区别：引用取决于「你的页面有多好切」，提及取决于「AI 认不认识你这家公司」。前者是工程，后者是经营。

两者是互相强化的：AI 先认识你（提及），用户问相关问题时它才会主动去检索你的官网——这时候页面可切块，就产生引用。所以提及是引用的前置条件。

1.2 怎么做引用（站内 · 自己可控）

前提：页面能被检索到（五个索引，见框架 §18.1）。然后是可切块 + 有独占信息：

动作量化效果

⚠️ 最后一条最容易被忽略：删掉一个页面，等于把之前攒下的引用一起删掉。

1.3 怎么做提及（站外 · 靠别人）

第一步不是发内容，是让 AI 知道你是谁、属于哪一类。

如果 AI 不知道你属于哪个品类，它没办法在「推荐 XX 类产品」时想到你。所以要有一句标准自我介绍，并在所有渠道用同一个说法：

「CHITEK 是一家低压有源谐波滤波器（AHF）与静止无功发生器（SVG）制造商，产品覆盖 8–300A…」

然后靠第三方独立叙述反复出现：

渠道具体做法注意
行业社区在电气 / 工控专业社区真实回答技术问题不带推销；真实从业者对话，AI 高度信任
目录 / 评测平台行业目录、协会名录、供应商库挑你们品类真正在用的平台，别硬套软件类平台

LinkedIn工程师 / 销售个人号的专业内容微软自家资产，同时喂 Bing 与 Copilot
客户证言让成交客户在公开平台留真实评价无法伪造 → AI 给高权重

⚠️ 提及必须带上下文：不是孤立地出现品牌名，而是「CHITEK 的 AHF 在××场景下……」。AI 要的是实体 + 品类的关联，一个孤立的名字它没法用。

2. 五个平台，五套信源偏好

别把 GEO 当成一个统一打法。 实测口径：只有 11% 的域名能同时被 ChatGPT 和 Perplexity 引用。

平台它要什么该往哪投

3. 信源结构正在变（2026 年实测）

跨 8 个平台的追踪数据（2026-07）显示：

  • 上涨：YouTube（创新高）、LinkedIn（从次要渠道跻身前五）、Facebook、Instagram

→ 共同点是「有可追溯的发布主体 + 实时更新」

  • 回落：Wikipedia、NIH、Statista

→ 共同点是「结构化程度高、更新频率低、内容形态统一」

原因很直接：参考类信源权威但更新慢、缺具体场景。当 AI 要回答「需要经验、需要当下状况、需要实操细节」的问题时，它们提供不了。

⚠️ 一个必须知道的突变案例：2026-08-08 OpenAI 调整了 query fanout 机制，改用 site: 操作符锁定可信域名——Reddit 在 ChatGPT 引用中的份额从 3.83% 跌到 0.52%，一周掉了 86.4%。ChatGPT 转而更多引用官方信源与直接网站。

教训：平台的信源偏好会突变，押单一渠道等于押平台的产品决策。要建的是多源矩阵，不是某个平台的最优解。

4. 站外动作：分三层做

第一层 · 实体层（前提，必须最先做）

⚠️ 顺序错了后面全部白做——实体没理清，AI 可能把引用给到同名竞品。

  • 统一一个清晰的品类描述，然后让所有渠道对齐：官网（首页 / About / 产品页）、LinkedIn 公司页、Crunchbase 类数据库、评测平台、维基 / Wikidata（若符合收录条件）、过去两年的所有新闻稿与署名文章
  • 品牌名 / 产品名 / 型号 / 创始人名，在所有地方用同一个写法
  • Organization schema 加 sameAs，指向所有已验证档案
  • 公司在各处引用的自身数据（成立年、产能、客户数）必须完全一致

实测反馈：只做实体统一这一步，就有品牌把 ChatGPT 引用率翻倍——还没写一个字的新内容。

第二层 · 第三方信源（主力）

类型具体载体为什么有效
评测平台G2、Capterra、TrustRadius、Gartner Peer InsightsAI 直接读结构化评测数据
社区讨论Reddit、LinkedIn 讨论、垂直行业论坛真实从业者对话，难以伪造 → AI 高度信任
行业媒体垂直媒体 > 综合媒体⚠️ 垂直媒体被引用频率正在超越综合媒体：产能压在一个赛道，颗粒度更细、更结构化
榜单 / 汇总页「最佳 XX 厂商」类文章⚠️ AI 引用常来自传统搜索前列 → 加入已排在 Bing / Google 前几名的榜单页，比自建新页快得多
客座内容第三方平台上用自己的话复述你的核心主张独立来源重复同一个事实 = 佐证（corroboration）

⚠️ 一条经验：被引用多的品牌，往往是在品类专属媒体上有几篇报道，而不是在五十个泛高权重博客上都留过名。具体 > 数量。

第三层 · 内容信用（加速）

  • 专家引述、原创数据、具体统计（量化效果见 §6）
  • 具名作者 + 可核查的作者档案（LinkedIn、行业署名）
  • 视频：YouTube 引用量创新高——一场产品演示或技术讲解，是 AI 能抓取的多模态信源

5. 权重怎么才高：六个变量

变量说明
① 信源层级权威媒体 / 标准机构 ＞ 行业垂直 ＞ 协会 / 地方 ＞ 自媒体。一个高权重信源可能抵上百个低权重
② 实体一致性名称与描述在所有渠道统一（前提条件，见 §4）
③ 多样性多个独立来源都在说你，远强于一个来源反复说
④ 稳定性⚠️ 19.3% 的 AI 引用链接已失效——频繁变动或无法访问的信源会被逐步降低优先级。链接别断，页面别删
⑤ 新鲜度90 天内更新的页面，被引用概率是 12 个月以上页面的 2.4 倍
⑥ 独占信息别人没有的数据、实测、配置、行业判断——AI 不引用到处都有的常识

7. 什么别做

  • ❌ 关键词堆砌：−8%，且不产生任何信任
  • ❌ 批量 AI 生成内容：不建立实体权威，而是稀释它
  • ❌ 到处写「我们是最领先的 XX」：被判为推广语，常反而降低抽取率
  • ❌ 买「保证被 AI 引用」的服务：站外是慢变量（以季度计），承诺即时见效的都是卖幻觉

8. 衡量：Share of Model

传统排名看不见 GEO 的产出——一次好的 AI 提及往往不产生任何点击。

所以业界收敛到的核心指标是 Share of Model（SoM）：在一组固定的买家提问上，你的品牌出现频率 vs 竞品。

配套三个数：

指标含义
提及率AI 答案里出现你品牌的频率
引用率AI 把你的域名列为来源的频率
描述准确度 / 情感它怎么描述你（是否过时、是否说错）

⚠️ 同一个问题在不同时间问会得到不同答案——必须重复采样，别用单次结果下结论。

9. 时间预期（别被忽悠）

动作见效周期

第一部分 · A 线：喂搜索与 AI

2. 为什么社媒是 AI 的最强信源

Ahrefs 对 7.5 万品牌的研究，把各类信号与 AI 可见性的相关系数排了个序：

信号相关系数
YouTube 提及（品牌名出现在视频标题 / 字幕 / 描述里）0.737
品牌网页提及0.66–0.71
品牌锚文本0.628
品牌搜索量0.466
域名评级0.266–0.326
网站页面数量0.194

⚠️ 两条结论直接改变了做法：

  1. 社媒提及比外链和域名权威更重要 —— 传统 SEO 的两大支柱在 AI 可见性里权重很低。
  2. 页面数量几乎没关系（0.194） —— 这直接反驳了「批量生产页面堆量」的策略。堆 100 个薄页面，不如让 20 个创作者在视频里念一次你的名字。

背后的原因也清楚：GPT-4 的训练用了超过 100 万小时的 YouTube 转录数据，而Google AI Mode 引用 YouTube 的次数多于任何其他域名。

⚠️ 另一条关键规律：体量胜于广度。 「在 20 个小创作者的低播放视频里被提到」强于「出现在一条爆款视频里」。所以不要盯着大 V，铺开面比单点爆量重要。

3. YouTube：A 线第一优先级

为什么第一：数据在上面，而且它是唯一同时具备「视频说服力」和「AI 可读性」的载体。

⚠️ 视频被 AI 引用的通道是文本，不是画面。 AI 读不了视频流，它读的是：

动作具体做法
① 逐字稿口播内容转成文字，放进视频描述区或配套文章
② 章节标记时间轴加目录：00:00 产品概述 / 02:30 技术参数 / 05:00 应用案例
③ 描述区文本写清「这是什么、解决什么问题、参数是多少」——带品类词与具体型号

同样一条视频，有没有完整的文字说明，被引用的概率完全不同。

内容形态（按优先级）：

  1. 技术讲解 —— 谐波是怎么产生的、AHF 和 SVG 到底怎么选（最能被引用）
  2. 产品演示 —— 一台设备从接线到运行
  3. 现场调试 / 工厂实拍 —— 真实感，也是 B 线的好素材
  4. 故障排查 —— 「THD 超标怎么一步步定位」

4. LinkedIn：A 线第二优先级

⚠️ 2026 年 3 月 12 日 LinkedIn 做了算法大改（统一 feed 架构 + LLM embedding + 生成式推荐），几个数字必须先知道：

事实数据
全平台自然流量下降约 50%
公司页获得的 feed 分配仅 5%
个人资料页的 feed 分配65%
个人号 vs 公司页曝光 2.75 倍、互动 5 倍

结论很硬：LinkedIn 的自然触达靠个人号，不靠公司页。 公司页保留（用于广告、招聘、背书），内容主战场挪到工程师 / 销售 / 管理层的个人号。

新算法的核心指标是 Depth Score（停留时间 + 评论深度 + 收藏 + 私密分享）：

  • 停留时间排第一 —— 30 秒以上的阅读显著加分
  • 收藏和私密分享是最高价值信号 —— 说明「这人觉得有用到要留下来」
  • 问自己一个问题：这篇内容，有人会收藏吗？ 不会，就别发

两个明确的惩罚：

  • ❌ 互动诱饵（「同意就评论 YES」）→ 被检测并压制
  • ❌ 正文里的外链 → 60% 曝光惩罚（此前约 30%）→ 链接改放第一条评论

高表现的格式：轮播图 / 文档帖的停留时间是纯文本的 2–3 倍。

节奏：

  • 每周 2–3 篇高质量（每天发反而有害——算法会压制）
  • 前 30 分钟的互动质量比 48 小时总量更重要
  • 内容配比：40% 价值 / 30% 故事 / 20% 观点 / 10% 推广

5. 行业社区

Reddit、Eng-Tips、专业论坛、LinkedIn Groups。

⚠️ 只能真实回答技术问题，不能推销。 AI 对这类内容信任度极高，恰恰因为它无法被伪造——真实从业者在真实问题下的真实回答。

一条反常识的经验：在技术社区里认真回答 20 个问题带来的 AI 引用，可能超过十篇官网文章。

AI 读图主要靠文件名、alt 文本、图注、周边段落，不是像素识别。

7.4 怎么选：三条规则

  1. 按市场选 —— 客户在哪个市场，就投那个市场的平台生态

11. 一条内容，四处使用

工业品做内容的瓶颈是产能，不是创意。所以一次产出要拆开用：

这也是为什么 A 线和 B 线不该分开做——同一份素材，换个形态就是两个渠道的内容。
